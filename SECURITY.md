## Joy Security

This section is generated by [Joy](https://github.com/joyint/joy), the
product-management tool this project uses. It covers only Joy's own
files, not the project's overall security policy.

Joy keeps one file per member under `.joy/members/`. It says what the
member is (`type`) and, under `identity`, the name the member goes by
with the values that prove who they are. Keyword-based secret scanners
may flag some of these values. None of them is a secret: they are public
keys, public inputs to key derivation, or ciphertext. No passphrase,
recovery key or private key is ever written to the repository.

### What a member file holds

| Field | What it is |
| --- | --- |
| `verify_key` | The member's Ed25519 public key; it verifies their signatures. |
| `kdf_nonce` | Public salt for Argon2id key derivation. |
| `seed_wrap` | The member's identity seed, encrypted with AES-256-GCM under a key derived from their passphrase and `kdf_nonce` via Argon2id (64 MiB, 3 passes). |
| `seed_wrap_recovery` | The same seed, encrypted under a key derived from a random 32-byte recovery key. Joy shows the recovery key once and never stores it. |
| `enrollment_verifier` | Argon2id digest of a one-time onboarding password; removed when it is redeemed. |
| `delegation_verifier` | Public key of a person's delegation to an AI member; the private key stays on the person's machine (mode 0600). |
| `email_tag` | Anonymous mode only: a one-way HKDF-SHA256 tag of the member's e-mail address. Joy's core library, which the CLI, the app and the platform share, compares it against a known address to find the member. |
| `members_wrap` | Anonymous mode only: the member's wrap of the key for `.joy/members.yaml`. |
| `origin.signature`, `granted.signature` | Ed25519 signatures of the member who added a person (`origin`) or set what an AI member may do (`granted`). |

### Passphrase strength

Anyone who can read the repository can try passphrases against
`seed_wrap` offline. Argon2id (RFC 9106) makes every guess expensive;
how long a passphrase holds depends on the passphrase. No minimum is
enforced on the passphrase; what joy shows while a new one is typed is
the zxcvbn estimate of the `joy-passphrase` crate, in bits and five
levels. Below 28 bit joy keeps a new passphrase only after the person
confirms "I know and accept the risk."

### E-mail addresses

By default a member's e-mail address is the name under `identity`, in
clear text. A project that wants no addresses in its repository runs
`privacy: anonymous`: each person then goes by an opaque id
(`m-<short>`), and the addresses live only in the encrypted
`.joy/members.yaml`, readable by members alone. Git committer identity
and history from before the switch are out of Joy's reach.

### Reporting a security issue

Report security issues in Joy itself via
[GitHub Security Advisories](https://github.com/joyint/joy/security/advisories/new)
in the Joy repository. Do not open public issues for them.
